# agent-api (Part 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the mock's chat with a real `agent-api`. It runs a Strands agent on DeepSeek that reads real RDS/Aurora through the AWS MCP Server, limited to databases with a scope tag, and proposes change requests that Approvals picks up.

**Architecture:** A new uv workspace member `services/agent_api` (FastAPI, sync SQLAlchemy Core on Postgres) serves conversations and runs natively. It passes change-request, audit and report endpoints through to the mock, and writes proposed CRs and audit rows through two new internal mock endpoints. Each run executes in its own worker thread, which drives a Strands `Agent`. The AWS tools come from the MCP server; our own tools list the in-scope databases and propose changes. One hook provider guards every AWS command, filters every result, times tool steps and writes run events. Pure modules (scope, guard, filter, proposals) carry the safety logic and are tested in isolation with fakes. Nothing in the test suite talks to AWS or DeepSeek.

**Tech Stack:**
- Python 3.12, uv workspace, ruff (line length 120), pytest
- FastAPI and httpx
- SQLAlchemy 2 Core: psycopg 3 for Postgres, sqlite for tests
- `strands-agents` (with the `openai` extra), boto3/botocore (Stubber in tests)
- `mcp-proxy-for-aws` (run with uvx inside the image)
- Postgres 16, Streamlit 1.67 (frontend banner only)

**Spec:** `docs/superpowers/specs/2026-11-19-agent-api-design.md` (the "design"). It builds on `docs/superpowers/specs/2026-11-14-db-ops-frontend-design.md` (the "part 1 spec"). Contract: `contracts/agent-api.yaml`.

## Global Constraints

- **Fixed contract:** `contracts/agent-api.yaml` and the event shapes in part 1 §7.1 don't change. All existing tests (`uv run pytest -q`) keep passing.
- **Identity:** every endpoint requires the headers `X-DBOps-User` and `X-DBOps-Service-Token`. The role always comes from `users.yaml`, never from the caller.
- **Errors:** errors use `{"error": {"code", "message"}}`. Codes are `401 unauthenticated`, `403 forbidden_role`, `404 not_found`, `409 run_active` and `422 validation_error`.
- **Scope tag:** `DBOPS_SCOPE_TAG_KEY`/`DBOPS_SCOPE_TAG_VALUE`, default `dbops:demo` / `true`. Regions come from `DBOPS_AWS_REGIONS`, default `us-east-1`.
- **Scope rules:**
  - A tagged Aurora cluster brings all its member instances into scope.
  - A tagged member instance brings in only itself.
  - Identifiers compare case-insensitively, because AWS lowercases them.
- **Out-of-scope wording:** a reference to an out-of-scope database is refused with exactly "unknown database". The wording is the same whether or not the database exists.
- **Fail closed:** an unparseable command is refused, and an unrecognised result shape is replaced by an error. A failed scope lookup fails the run with "Couldn't read the database list from AWS".
- **Run limits:** `RUN_MAX_TOOL_CALLS=15` ends the run with "Stopped after 15 AWS calls". `RUN_TIMEOUT_S=300` ends it with "Stopped after 5 minutes". A run still `running` at startup becomes `failed` with "agent-api restarted".
- **Truncation:** a tool result is cut to 20 KB (20480 bytes of JSON) with `"truncated": true`.
- **Title:** a conversation's title is its first message, stripped and cut to 60 characters.
- **No AWS writes:** propose tools never call an AWS write API. The IAM policy has no write actions.

## Review Focus

1. **Argument spellings the guard must still catch.** The equals form (`--db-instance-identifier=prod-x`), mixed case (`PROD-X`), a quoted ARN, and CloudWatch dimensions given as JSON or as shorthand (`Name=DBInstanceIdentifier,Value=prod-x`). Each must still be scope-checked. Pinned by `test_guard_argument_spellings` (Task 5).
2. **MCP result formats.** Results that arrive as a JSON string inside MCP text content, or that carry `Marker`/`NextToken`, must be parsed and filtered, not refused or passed through. Pinned by `test_filter_parses_text_content` and `test_filter_keeps_pagination_tokens` (Task 6).
3. **DeepSeek failing mid-stream** (401, 429, timeout) must end the run with `run_failed` and a plain message. The text already streamed stays in the assistant message. Pinned by `test_model_error_mid_stream` (Task 8).
4. **Two run starts racing on one conversation** must give exactly one `run_id` and one `409 run_active`. Pinned by `test_concurrent_start_one_wins` (Task 2), using a partial unique index.
5. **Pass-through of non-JSON and error responses.** Report downloads (bytes, `Content-Type`, `Content-Disposition`) and mock errors (409, 403) must arrive unchanged. Pinned by `test_passthrough_download_bytes` and `test_passthrough_error_status` (Task 3).

### Task 5: Command guard

**Files:**
- Create: `services/agent_api/src/agent_api/guard.py`
- Test: `services/agent_api/tests/test_guard.py`

**Interfaces:**
- **`ALLOWED_OPERATIONS: dict[str, frozenset[str]]`** is copied exactly from design §7.3.
- **`check_command(command: str, scope: ScopeSet, regions: tuple[str, ...]) -> str | None`** returns `None` when the command is allowed, or a refusal reason. The reasons are these exact strings:
  - `"only one AWS CLI command at a time"`
  - `"operation not allowed: <service> <op>"`
  - `"flag not allowed: <flag>"`
  - `"region not allowed: <region>"`
  - `"unknown database"`
  - `"could not parse command"`
- **`step_name(command: str) -> str`** gives, for example, `"rds.describe_db_instances"` for `aws rds describe-db-instances …`, and `"aws"` if the command can't be parsed.
- **How it parses:**
  - `shlex.split` with `punctuation_chars=True`. Any `|`, `;`, `&`, `>`, `<`, backtick or `$(` refuses the command.
  - The first token must be `aws`.
  - `--flag=value` is split into flag and value.
  - Database references are read from `--db-instance-identifier`, `--db-cluster-identifier`, `--source-identifier`, `--resource-name` (an ARN) and `--db-snapshot-identifier`/`--db-cluster-snapshot-identifier`. For the snapshot flags, only the scope of the snapshot's source is checked, and that happens in the filter, so here they are allowed.
  - CloudWatch `--dimensions` and `--metric-data-queries` are parsed in both JSON and shorthand forms, and every `DBInstanceIdentifier`/`DBClusterIdentifier` value must be in scope.

### Task 6: Result filter and truncation

**Files:**
- Create: `services/agent_api/src/agent_api/result_filter.py`
- Test: `services/agent_api/tests/test_result_filter.py`

**Interfaces:**
- **`filter_result(raw: Any, scope: ScopeSet) -> tuple[Any, bool]`** returns `(filtered_json, ok)`.
  - **Input:** `raw` may be a dict, a JSON string, or MCP content (`[{"type": "text", "text": "<json>"}]` or `{"content": [...]}`). The filter unwraps it and parses the JSON.
  - **Known top-level keys** are filtered as design §7.4 describes: `DBInstances`, `DBClusters`, `DBSnapshots`, `DBClusterSnapshots`, `Events`, `MetricAlarms`, `CompositeAlarms`, `Metrics`, `PendingMaintenanceActions`, `TagList`, `Datapoints`, `MetricDataResults`, `OrderableDBInstanceOptions`.
  - **Passed through unchanged:** the keys `Marker`, `NextToken`, `Label` and `Messages`, and the tag list for a resource that is in scope. The guard has already checked that resource.
  - **Shape rules:**
    - Each key is either filtered or passed through. Any other key, or an unparseable value, gives `({"error": "result withheld: unrecognised shape"}, False)`.
    - A composite alarm can't be tied to one database, so `CompositeAlarms` is filtered to an empty list.
- **`truncate(result: Any, limit: int = 20480) -> tuple[Any, bool]`** has the same semantics as `mock_backend.runs.truncate_result`. Copy it.

- [ ] **Step 1: Write the failing tests**, using the same scope as Task 5:
  - `test_filter_instances_and_clusters`: a mix of in-scope and out-of-scope entries keeps only the in-scope ones. A cluster member counts as in scope.

**Interfaces:**
- **`ProposalError(message)`** is the plain refusal returned to the model.
- **`Proposer(scope: ScopeResolver, rds_client_factory, mock: MockClient, prices: dict, clock=lambda: datetime.now(UTC))`** has these methods. Each returns the created CR (a dict from `MockClient`).
  - `modify_tags(caller, conversation_id, identifier, add: dict[str,str], remove: list[str])` (LOW)
  - `create_snapshot(caller, conversation_id, identifier)` (LOW): a cluster snapshot for a cluster, an instance snapshot for an instance. `params` is `{snapshot_identifier: "<db>-dbops-<yyyymmddhhmm>", snapshot_kind: "cluster"|"instance"}`.

  - `modify_instance_class(caller, conversation_id, identifier, to_class)` (HIGH)
- **Common rules:**
  - **Role:** the caller's role is re-checked against `required_role(tier)`. That is SAFE-WRITE for LOW and PRIVILEGED for MEDIUM/HIGH. A role that is too low raises `ProposalError("Your role (<role>) can't propose <change_type>")`.
  - **Scope:** an out-of-scope identifier raises `ProposalError("unknown database")`.
  - **Body:** the body is built as `POST /internal/change-requests` expects (Task 1), with `requested_via` defaulting to chat. `database` comes from the `ScopedDb`.
- **Tags:** `diff` has one entry per added, changed or removed tag, `field` being `tag:<key>`. `params` is `{"before": {...}, "after": {...}}`, and the rollback is "Re-apply the previous tag set".
- **Resize:**
  - A cluster identifier raises `ProposalError` listing the members, for example `"aur-1 is an Aurora cluster; resize one instance: aur-1-w (writer, db.r6g.large), aur-1-r (reader, db.r6g.large)"`.
  - `params` is `{from_class, to_class, cluster_identifier?}`.
  - `impact` is "Writer instance: ~1–2 min failover to a reader during the change" for an Aurora writer, "Reader instance: no write downtime; reads on this instance pause while it restarts" for an Aurora reader, and "~5–10 min downtime (Multi-AZ failover)" for plain RDS.
  - `maintenance_window` is built from the instance's `PreferredMaintenanceWindow`, with `inside_now` and `next_start` computed against the clock.
  - The rollback is `["Snapshot taken automatically before the change", "Modify back to <from_class>"]`. The CR id isn't known until the mock assigns it, so the snapshot isn't named here.
  - `to_class == from_class` raises `ProposalError("<db> is already <class>")`.
- **Restore test:**
  - The source snapshot is the given one or the latest available one (`describe_db_snapshots`/`describe_db_cluster_snapshots`, newest `SnapshotCreateTime`). No snapshot raises `ProposalError("<db> has no snapshot to restore from")`.
  - The smallest class comes from `describe_orderable_db_instance_options(Engine=…)`, preferring `db.t4g.micro` → `db.t4g.small` → `db.t4g.medium` → `db.t3.micro`, whichever is orderable first.

**Files:**

**Interfaces:**
- **`tools.build_tools(caller: Caller, conversation_id: str, scope: ScopeResolver, proposer: Proposer, emit: Callable[[dict], None]) -> list`** returns Strands `@tool` functions:
  - Always `list_demo_databases()`, which returns `[{identifier, kind, engine, instance_class, region, status, cluster, members}]`.
  - The propose tools for the caller's role, from the design §7.2 table.

  A propose tool calls the `Proposer`. On success it calls `emit({"type": "change_proposed", "change_request_id", "change_type", "risk_tier"})` and returns `{"change_request_id": …, "status": "pending", "note": "Needs approval on the Approvals page"}`. - **`hooks.RunHooks(HookProvider)`** is constructed with `(run_id, caller, scope_set, regions, aws_tool_names: set[str], emit, audit, max_tool_calls, cancelled: Callable[[], bool], clock=time.monotonic)`.
  - **`BeforeToolCallEvent`:**
    - It counts the call. Going past `max_tool_calls` sets `cancel_tool` and records that the limit was reached.
    - A tool in `aws_tool_names` is checked with `guard.check_command(input["command"], …)`, and a refusal sets `cancel_tool = reason`.
    - It always emits `tool_call_started` with `tool_call_id = toolUseId`. The `name` is `step_name(command)` for AWS tools and the Python tool name otherwise, and the `args` are the tool input.
    - It records the start time.
  - **`AfterToolCallEvent`:**
    - For AWS tools with a successful result, it applies `filter_result`, replacing the result the model sees.
    - It then applies `truncate`.
    - It emits `tool_call_finished` with `status` `ok`/`error` (a refusal, a withheld result or a tool error all count as `error`) and `duration_ms`.
    - It calls `audit({"user", "action": "chat.tool_call", "tool": name, "database": <first db reference or None>, "result": "ok"|"error"|"refused"})`.
- **`agent_factory.build_agent(settings, caller, conversation_id, history: list[dict], aws_tools: list, hooks: RunHooks, extra_tools: list, model=None) -> strands.Agent`**:
  - With `model=None` it uses `OpenAIModel(client_args={"api_key": settings.deepseek_api_key, "base_url": settings.deepseek_base_url}, model_id=settings.deepseek_model)`.
  - `system_prompt` comes from `prompt.system_prompt(caller.role, scope_set)`, following design §7.6.
  - `messages` are the history converted to Strands message format (user and assistant text only; tool steps are not replayed).
  - `callback_handler=None`.
- **`runner.Runner(settings, store, scope: ScopeResolver, proposer, mock: MockClient, aws_tools_provider: Callable[[], ContextManager[list]], model_factory: Callable[[], Any] | None = None)`** implements `RunnerProtocol.start` (Task 2).
  - **Thread:** each run gets a daemon thread running `asyncio.run(self._drive(...))`.
  - **Order of operations:**
    1. `scope.current()`. On `ScopeUnavailable`, run_failed.
    2. Emit `run_started`.
    3. Post a `chat.message` audit row.
    4. Enter `aws_tools_provider()`, then build the agent.
    5. Iterate `agent.stream_async(message)`.
  - **Text:** `data` chunks go into a buffer, which is flushed as `text_delta` when 100 ms have passed or before any other event.
  - **Every loop pass checks:**
    - `store.cancel_requested(run_id)`: emit `run_cancelled`, then stop.
    - the deadline (`run_timeout_s`): run_failed "Stopped after 5 minutes".
    - the hooks' limit flag: run_failed "Stopped after 15 AWS calls", taking the value from settings.
  - **Errors:** any exception from the model (including `openai.APIError`) becomes `run_failed` with `"The language model call failed: <short type/message>"`.
  - **Finally:** it flushes the text, assembles the assistant message from the run's events (same rules as `mock_backend.runs._assistant_message`, including the `⛔ error` suffix), writes it with `store.add_message`, and calls `store.finish_run`.
- **Test fakes:**

Each turn is a list of `{"text": str}` or `{"tool": name, "input": dict}` items, and `stream()` yields the matching Strands stream events: `messageStart`, `contentBlockStart`/`Delta`/`Stop` and `messageStop` with `stopReason` `tool_use` or `end_turn`. `turns` items may also be an exception instance, which is raised from `stream()`.
  - `fakes.fake_call_aws(responses: dict[str, Any])` is a Strands `@tool` named `call_aws`. It records the commands and returns the canned JSON per service and operation.
